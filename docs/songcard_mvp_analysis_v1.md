## 2. 수익·운영 접점 (읽은 것만)
- 가격 앵커 $29, 추가 상품 판매, **리액션 영상 이벤트**(채택 시 네이버페이 상품권, 최대 10만 원).
- 운영: 이메일 지원 하나, 주문 조회는 이메일로. 사업자는 미국 법인(애틀랜타 주소). 약관에 「가사 생성에 제3자 서비스 사용」.
- ⚠ FAQ의 「자동화되어 있지 않습니다·실제 작사가·프로듀서」와 약관 §2·§6의 「가사 생성·음악 생성」이 **서로 긴장**한다.
  우리는 따라 하지 않는다. **샘플과 실제 제작을 카드에 표시**하는 쪽이 우리 원칙과 맞다.

## 3. 우리 적용점
1. **SP는 코퍼스로 만든다** — 장르·목소리·목적 선택을 `mvp/songcard/sp_builder.py`가 SP로 바꾼다. 분위기·악기·보컬 어휘는
   `sunolang.db` expr_concepts를 **읽기 전용으로 그 자리에서 조회**해 쓰고, 관측 30회 미만이거나 dead zone이면 거절한다.
   장르 라벨은 **요청층**이라고 따로 표시한다(관측 아님). 참고 서비스에는 없는, 우리만 가진 층이다.
2. **가사는 우리 몫이 아니다** — 파이프라인이 LM 라인에 가사 발주서를 내고, 담당 슬롯은 kee가 지정한다.
3. **생성은 기존 sunomusic 채널**을 쓴다. 발주서 파일명 = `{request_id}_gen_L{가사판}_V{보컬판}` ⇒ 같은 판을 두 번 발주할 수 없다.
4. **오디오 회수** ⛔ `cdn1.suno.ai/{uuid}.mp3` 직링크가 **403**이다(09-25 실측). 그래서 sunomusic이 파일을 넘겨 주고,
   우리가 sha256 자산 목록에 올려 직접 서빙한다.
5. **얇은 호환층**(LM4 대기 안 함): request_id·legacy_gid·takes[suno_uuid·selected]·lyrics_versions·vocal_version·asset_manifest.
   JSON 한 파일(`mvp/songcard/var/`, **git 밖** — 고객 사연)에 둔다.
