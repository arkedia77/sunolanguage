## 2. 흐름 (상태기계 — 이미 구현·실측 1건 완주)

```
[사용자]  목적 선택 → 폼 제출 ──POST /api/requests──┐
[서버]                          received → lyrics_pending → lyrics_ready
[LM라인]                         가사(leomusic3)  ↑                ↓
[서버]                          generation_queued → generating → audio_ready → ready
[사용자]  상태 폴링(5초) ────────────────────────────────────┘ → 카드·공유·재요청
```
- **중복 방지 4중** 이미 있음: 접수 `client_key` · 발주서 파일명 `{id}_gen_L{가사판}_V{보컬판}` · 재요청 `redo_key`+열린 건 1개 · 오디오 sha256 자산 id.
- **납품본 단위**: take·가사판·보컬판 한 묶음만 카드에 뜬다. 새 판 만드는 중에도 이전 납품본이 보인다.
- ⛔`cdn1.suno.ai/{uuid}.mp3` = **403**(09-25·재확인) ⇒ 오디오는 **파일로 받아** `audio-in`으로 붙인다. 자동 다운로드 경로는 없다.

## 4. 처리 방식 — v1은 «반자동»(사람 1명이 3번 붙는다)

| 단계 | 누가 | 자동/수동 |
|---|---|---|
| 접수 → 발주서 생성 | 서버 | **자동**(`var/outbox/`에 파일로 떨어짐) |
| 발주서 → leomusic3 발신 | **사람**(kee 지정 운영자) `scripts/send_msg.py` | **수동 — 일부러**(아래 5) |
| 가사 수령 → `lyrics-in` | 운영자 CLI | 수동 |
| Suno 생성(sunomusic) → mp3 파일 수령 → `audio-in` | sunomusic + 운영자 | 수동(403 때문에 파일 전달) |
| `publish` → 카드 게시 | 운영자 CLI | 수동 1줄 |

**생성 전 내용 확인**(실존 인물 비방·성적·혐오)은 **발주 발신이 수동이라 그 지점이 곧 심사 지점**이다 — 자동 필터를 새로 만들지 않는다(v1 하루 5건 상한에서 사람이 전수로 본다).
완전 자동화는 v2 — ⛔v1에서 손대지 않는다(발주≠범위확장).
