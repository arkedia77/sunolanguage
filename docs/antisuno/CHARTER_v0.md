## 0. 한 줄

sunolang이 3년치로 세운 건 **「Suno의 자」**다. antisuno가 세우려는 건 **「자가 엔진을 건너가는가」**다.

## 1. 왜 지금인가 — 방아쇠는 우리 값이 아니라 남의 반례다

08-29 leomusic3 회신(M4): 같은 곡·같은 SP로 **MiniMax Music 3.0**에 우리 `suno_lyrics`를 무변경 이식하니
곡 **중간에 낀 긴 브라켓 2건을 그대로 노래로 불렀다**(bigram recall 0.92·1.00 · 합 24.5초 = 트랙의 13.9%).
짧은 브라켓 8건과 인트로·아웃트로 자리의 긴 브라켓은 전건 0.00.
근거: `agent-comm:projects/sunolanguage/messages/sunolanguage_leomusic3_20260829_195500_타엔진표본…json`

⇒ 우리 대장 **D052⒝**(「브라켓 안은 큐로 읽고 안 부른다」)는 코퍼스 4,166건 전건이라는 강한 값이지만,
그 값이 말하는 건 **「Suno가 그렇다」**이지 **「음악 LLM이 그렇다」**가 아니었다.
★**우리는 지금까지 엔진 성질과 매체 성질을 구분할 자를 가진 적이 없다.** antisuno는 그 자를 만드는 일이다.

## 2. 이 프로젝트가 답하는 질문

| # | 질문 | 왜 이게 값인가 |
|---|------|----------------|
| Q1 | 각 엔진의 **통제면(control surface)**은 정확히 무엇인가 — 사람이 타이핑/설정해서 음악을 바꿀 수 있는 면 전부 | 통제면을 모르면 「안 먹혔다」와 「전달된 적 없다」를 못 가른다 (08-29 bar수 정정과 같은 실패) |
| Q2 | 우리 대장의 D축 주장들은 **엔진 조건부인가 일반인가** | 일반이면 이식 가능 자산, 조건부면 Suno 전용 자산 |
| Q3 | 우리가 쌓은 자산(사전 v3.3·브라켓 팔레트·SP 문법) 중 **무엇이 이식되고 무엇이 깨지는가** | leomusic3 실측: 무변경 이식 시 13.9% 파손 |
| Q4 | Suno에 **없는** 통제면이 다른 엔진에 있는가 (실시간 스티어링·composition plan·weighted prompt·음소 편집) | 없는 걸 아는 게 있는 걸 아는 것보다 값이 클 수 있다 |

## 3. 범위 / 비범위 (★발주≠범위확장)

**범위(Phase 0)**: 문헌·문서 조사만. 엔진별 통제면 대장 작성. 우리 D축과의 교차표.
**비범위(Phase 0)**: 계정 개설·과금·실제 생성·오디오 회수. 코퍼스 관리(P0 상시 임무)는 그대로 우선.
**비범위(영구)**: 타 엔진으로 상업 발매. antisuno는 **통제 연구**이지 생산 라인이 아니다.

## 4. 산출물 3종

1. **엔진 통제면 대장** `docs/antisuno/control_surface_register_v*.md` — 엔진 × 통제 채널 × 문법 × 파라미터명 × 출처URL
2. **교차 대장** `docs/antisuno/cross_engine_matrix_v*.md` — 우리 D축 × 엔진 (엔진조건부 / 일반 / 미측정)
3. **이식성 규칙** `docs/antisuno/portability_rules_v*.md` — 「엔진 중립 정본은 무엇인가」의 실측판
   *(leomusic3 `stage_6b` 독스트링의 「엔진 중립 정본 = song_form·style_prompt」가 지금은 적혀만 있고 잰 적 없는 경계다)*

## 5. 근거 등급 — 두 축을 섞지 않는다

**외부 문서 축 `E`** (이번에 신설, Phase 0의 전부):
`E1` 공식 문서·API 레퍼런스 / `E2` 공식 블로그·릴리스노트 / `E3` 논문·기술리포트 / `E4` 커뮤니티 관측(미검증)

**실측 축 `M`** (기존, `docs/directive_register_v1_3.md` §1):
`M1` 전수 / `M2` 표본 / `M3` 외부실물을 내가 직접 잼 / `M4` 타 프로젝트 실측

★**E는 M이 아니다.** 「문서에 있다」는 「그렇게 동작한다」가 아니다.
Phase 0 산출물에 M급 값이 하나라도 들어가면 그건 규약 위반이다 — 유일한 예외가 위 §1의 leomusic3 M4 1건이고, 출처를 값 옆에 붙인다.

## 6. 사전등록 — Phase 0에서 무엇을 보면 무엇이 무너지는가

| 예측 | 반증 조건 |
|------|-----------|
| P1. 대부분의 엔진은 **가사 칸이 프롬프트와 분리**돼 있다 | 조사 대상 상용 엔진 절반 이상이 프롬프트 한 칸뿐이면 P1 기각 |
| P2. **구조 태그 문법을 공식 문서로 공표한 엔진은 소수**다 (Suno가 공표 안 하는 게 업계 관행) | 공식 태그 목록 문서를 가진 엔진이 과반이면 P2 기각 ⇒ 우리 대장 D008·D026·D036(「Suno는 문법을 공표 안 한다」)의 해석이 바뀐다 |
| P3. 「대괄호 안은 안 불린다」는 **엔진 조건부**다 | 조사한 엔진 중 대괄호를 큐로 읽는다고 **문서로** 명시한 곳이 대다수면 P3 약화(일반 성질 쪽) |
| P4. Suno에 없는 통제면이 최소 3종 존재한다 (실시간 weighted prompt · composition plan JSON · 음소 단위 편집) | 3종 미만이면 P4 기각 |

★이 표는 **조사 착수 전에 적었다**. 결과를 보고 고치지 않는다 — 틀리면 틀린 대로 §7에 남긴다.

## 7. Phase 계획

- **Phase 0 · 조사** (지금) — 5클러스터 외부검색 위임 + 교차검증 → 통제면 대장 v0
  - 클러스터: `lyria`(Google) · `minimax_cn`(MiniMax·Mureka·SkyMusic) · `vocal_synth`(ACE Studio·Synth V·VOCALOID) · `western_commercial`(Udio·ElevenLabs·Riffusion·Stable Audio) · `oss_research`(YuE·DiffRhythm·ACE-Step·MusicGen — 조건화 내부구조)
- **Phase 1 · 교차 대장** — 우리 D축 × 엔진 매핑. 어느 축이 「엔진조건부」로 확정되는지.
- **Phase 2 · 통제쌍 설계(사전등록)** — 실측 전에 자부터. leomusic3 통제쌍 n=1의 확장 설계(어절수 경계·위치 축).
- **Phase 3 · 실측** — LEO 승인 후에만. 계정·과금 필요분은 별도 발주.
